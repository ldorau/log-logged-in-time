Login Time Logger - Installation
================================

Prerequisites
-------------
1. Sign in with an account that has Administrator rights.
2. Know two Windows logon names (SAM / DOMAIN\user / UPN, not display names):
   - AdminUsername: administrative account that owns install/config/logs
     (profile path becomes C:\Users\<sam>, e.g. AdminName -> C:\Users\AdminName)
   - TargetUsername: account whose unlocked login time is measured
     (for testing, AdminUsername and TargetUsername may be the same account)
3. The built-in Administrator account / BUILTIN\Administrators group is not required.


Step 1 - Optional config tweaks
-------------------------------
AdminUsername and TargetUsername are passed on the command line (required).
Optional settings remain in config\config.json (poll interval, SCP, updates):

  {
    "TargetUsername": "",
    "AdministratorProfile": "",
    "LogDirectory": "",
    "PollIntervalSeconds": 5,
    "UpdateEnabled": false,
    "UpdateRepoUrl": "https://github.com/ldorau/log-logged-in-time.git",
    "UpdateBranch": "main",
    "UpdateClonePath": "",
    "ScpOnLockEnabled": false,
    "ScpHost": "",
    "ScpUser": "",
    "ScpRemoteDirectory": "",
    "ScpPort": 22,
    "ScpIdentityFile": "",
    "ScpKnownHostsFile": ""
  }

Accepted account name forms:
  - Local SAM:     UserName
  - Domain:        CONTOSO\UserName
  - UPN:           UserName@contoso.com

Leave LogDirectory empty to use:
  <AdministratorProfile>\LoginTimeLogs


Step 2 - Install
----------------
Option A - One-file bootstrap (download only Bootstrap-Install.ps1)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. Open PowerShell as Administrator.
2. Allow scripts for this session only:
     Set-ExecutionPolicy -Scope Process Bypass
3. Download and run the bootstrap (both account names required):
     Invoke-WebRequest `
       -Uri "https://raw.githubusercontent.com/ldorau/log-logged-in-time/main/Bootstrap-Install.ps1" `
       -OutFile "$env:TEMP\Bootstrap-Install.ps1"
     & "$env:TEMP\Bootstrap-Install.ps1" -AdminUsername AdminName -TargetUsername UserName -StartNow

   Arguments: (1) AdminUsername (2) TargetUsername (may be identical for testing).
   The bootstrap installs Git if missing, clones to %USERPROFILE%\log-logged-in-time,
   then runs scripts\Install.ps1 with those accounts.
   Optional: -ClonePath "D:\src\log-logged-in-time"  -Force

Option B - From an existing project folder
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. Open PowerShell as Administrator.
   (Right-click Start -> Terminal (Admin) / Windows PowerShell (Admin))

2. Change to the folder that contains this project, for example:
     cd C:\Path\To\log-logged-in-time

3. Allow scripts for this session only:
     Set-ExecutionPolicy -Scope Process Bypass

4. Install and start immediately:
     .\scripts\Install.ps1 -AdminUsername AdminName -TargetUsername UserName -StartNow

   Or install only (starts automatically at next boot):
     .\scripts\Install.ps1 -AdminUsername AdminName -TargetUsername UserName

Install.ps1 first checks required software/components, then applies the two
account arguments and optional settings from config\config.json.
If any check fails, install stops with an error.

Prerequisite checks include:
  - Windows 10/11
  - Administrator elevation
  - PowerShell 5.1+ and Windows PowerShell (powershell.exe)
  - .NET ACL APIs
  - wtsapi32.dll (session lock detection)
  - ScheduledTasks module and required cmdlets
  - Project files present
  - AdminUsername and TargetUsername set and both accounts exist
  - Program Files write access
  - SessionQuery.cs compiles under Windows PowerShell (Add-Type)
  - Git for Windows (git.exe) only when UpdateEnabled is true
    (downloaded, Authenticode-verified, and installed silently if missing)
  - OpenSSH Client (scp.exe) only when ScpOnLockEnabled is true
    (installed via Windows capability if missing)

The startup task runs powershell.exe with -WindowStyle Hidden.

Self-update (background monitor; opt-in)
----------------------------------------
Disabled by default (UpdateEnabled=false). When enabled, once per day the
monitor checks https://github.com/ldorau/log-logged-in-time for a newer
commit (git ls-remote). Only that HTTPS GitHub repo URL is accepted.
If the tip differs from
  C:\Program Files\LoginTimeLogger\installed-commit.txt
it clones/pulls into
  <AdministratorProfile>\LoginTimeLogger\repo
copies updated src files into Program Files, then restarts via the
scheduled task (Start-ScheduledTask after exit) so monitoring stays under
Task Scheduler. Offline checks are postponed by 10 minutes.
Set "UpdateEnabled": true in config.json to enable.

SCP on lock (optional)
----------------------
Disabled by default (ScpOnLockEnabled=false). When enabled, on every lock
(or leaving unlocked-active) the monitor copies via OpenSSH scp:
  - today's unlocked-time-YYYY-MM-DD.log
  - errors.log
to ScpUser@ScpHost:ScpRemoteDirectory/ using key-based auth only.
Default identity file (if ScpIdentityFile is empty):
  <AdministratorProfile>\LoginTimeLogger\ssh\id_ed25519
Default known_hosts (if ScpKnownHostsFile is empty):
  <AdministratorProfile>\LoginTimeLogger\ssh\known_hosts
Requires OpenSSH Client (scp.exe) and a private key readable by SYSTEM.
Install.ps1 installs OpenSSH Client if missing, then validates scp.exe,
host/user/directory, and the identity file when ScpOnLockEnabled is true.


What the installer does
-----------------------
1. Reads settings from the template config\config.json in this project
   (the template file is not modified).
2. Writes the runtime config under AdministratorProfile (example):
     C:\Users\AdminName\LoginTimeLogger\config.json
   ACLs: AdministratorProfile account + SYSTEM full control; target user Deny.
   (Does not require BUILTIN\Administrators.)
3. Creates the log directory under AdministratorProfile with the same ACLs:
     C:\Users\AdminName\LoginTimeLogs
4. Copies monitor scripts (not the config) into:
     C:\Program Files\LoginTimeLogger
5. Registers scheduled task "LoginTimeLogger" pointing at that runtime
   config path:
     - Trigger: At system startup
     - Principal: NT AUTHORITY\SYSTEM
     - Run level: Highest


Verify installation
-------------------
Check the task, monitor process/mutex, and today's totals (Administrator PowerShell):
  .\scripts\Status.ps1

Test session / lock detection for the configured user:
  .\scripts\Test-Session.ps1
  Tip: lock the target desktop (Win+L) from another session and re-run to
  confirm LockSource / WtsSessionFlags on this host.

Calibrate lock/unlock detection (interactive; uses Win+L):
  .\scripts\Test-LockCycle.ps1
  Uses the current Windows user ($env:USERNAME) by default.
  Optional: .\scripts\Test-LockCycle.ps1 -TargetUsername someoneelse
  Does not use Administrator files.
  Starts scripts\LockCycleWatcher.ps1 (hidden STA); events go to:
    %TEMP%\LockCycle-<username>\session-switch.log
  1) Script confirms the current user is unlocked
  2) Press Win+L, then unlock as that user
  3) Return to the window and press Enter
  4) Script checks the TEMP event file for SessionLock + SessionUnlock
  (Same-session polling cannot observe Win+L; the process freezes.)

Optional: open Task Scheduler and confirm task "LoginTimeLogger" exists
and is Ready/Running.


View logs
---------
As Administrator, open the LogDirectory from config (example):
  C:\Users\AdminName\LoginTimeLogs

Files:
  unlocked-time-YYYY-MM-DD.log  - daily event log
  unlocked-time-summary.csv     - completed-day totals
  state.json                    - current-day running total
  service.log                   - diagnostics


Change the monitored user later
-------------------------------
Re-run install with the new measured account:
  .\scripts\Install.ps1 -AdminUsername AdminName -TargetUsername UserName -StartNow
This refreshes <AdministratorProfile>\LoginTimeLogger\config.json

Or edit TargetUsername in the runtime file as that admin user:
  C:\Users\AdminName\LoginTimeLogger\config.json
then restart the task:
  Restart-ScheduledTask -TaskName LoginTimeLogger
  (or Stop then Start the task)


Uninstall
---------
In an Administrator PowerShell from this project folder:

  Set-ExecutionPolicy -Scope Process Bypass
  .\scripts\Uninstall.ps1

To also delete log files:
  .\scripts\Uninstall.ps1 -RemoveLogs

If you used a custom AdministratorProfile in config.json, pass the same path:
  .\scripts\Uninstall.ps1 -AdministratorProfile "C:\Users\Admin" -RemoveLogs


Troubleshooting
---------------
- Prerequisite check failed:
  Read the [FAIL] lines from Install.ps1, fix each item, then retry.

- Any script error:
  Failures print a detailed ERROR DETAILS block to the screen and append
  the same text to a separate Administrator error log:
    <AdministratorProfile>\LoginTimeLogger\errors.log
  Monitor operational messages also go to LoginTimeLogs\service.log.
  If the admin profile path is not writable, a TEMP fallback is used:
    %TEMP%\LoginTimeLogger\errors.log

- Install says AdminUsername or TargetUsername is missing:
  Pass both arguments, for example:
    .\scripts\Install.ps1 -AdminUsername AdminName -TargetUsername UserName -StartNow

- Account was not found:
  Use local SAM, DOMAIN\user, or user@upn.domain — not the display name.

- Lock-cycle test fails on Phase 2 (never sees lock):
  Re-run .\scripts\Test-Session.ps1 while locked (from another session
  if needed). Confirm SessionFlags interpretation on this host.

- Task not running:
    Start-ScheduledTask -TaskName LoginTimeLogger
  or reboot. Status.ps1 also reports monitor mutex/process liveness.

- Wrong user measured:
  Re-run Install.ps1 with the correct -TargetUsername and -StartNow.

- Log folder missing / access denied for admin:
  Confirm -AdminUsername matches a real local profile under C:\Users\.

- Monitored user can still see logs:
  Re-run Install.ps1 so ACLs are reapplied; confirm you are checking
  the LoginTimeLogs folder under the Administrator profile.
